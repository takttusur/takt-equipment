## Сервисы

Сервисы делать в папке Services

# UserService

Нужно создать интерфейс и сервис для работы с пользователями (IUserService и UserService).

У этого сервиса должно быть 2 метода:
1. GetUserByIdAsync(Guid userId): Task<User> - получение пользователя по его идентификатору.
2. GetCurrentUserAsync(): Task<User> - получение текущего аутентифицированного пользователя.

# UserRolesService

Нужно создать интерфейс и сервис для работы с ролями пользователей (IUserRolesService и UserRolesService).

У этого сервиса должно быть 2 метода:
1. CanRequestEquipmentAsync(Guid userId): Task<bool> - проверка, может ли пользователь запрашивать оборудование.
2. CanIssueEquipmentAsync(Guid userId): Task<bool> - проверка, может ли пользователь выдавать оборудование.

# User Entity
Вообще мы тут будем брать пользователей из внешней системы, но для упрощения задачи нужно создать сущность User с минимальным набором свойств:
- Guid Id
- string Username
- List<string> Roles

## EquipmentRequestsController

Нужно добавить в контроллер методы для обычного пользователя:

1. CreateEquipmentRequest: HTTP POST запрос - создание запроса на оборудование. 
   - Должен проверять, может ли текущий пользователь запрашивать оборудование с помощью UserRolesService. 
   - Если не может - возвращать 403 Forbidden.
   - Если может - создавать запрос и возвращать 201 Created.
2. EditEquipmentRequest: HTTP PUT запрос - редактирование запроса на оборудование.
   - Должен проверять, может ли текущий пользователь запрашивать оборудование с помощью UserRolesService. 
   - Должен проверять, принадлежит ли запрос текущему пользователю.
   - Если нет прави или чужой запрос - возвращать 403 Forbidden.
   - Если запроса нет то возвращать 404 Not Found.
   - Если может - редактировать запрос и возвращать 200 OK. Редактировать можно только текст и даты
   - Статус запроса редактировать нельзя.
   - Если запрос уже в статусе Approved или Rejected, то редактировать его нельзя - возвращать 400 Bad Request.
3. GetMyRequests: HTTP GET запрос - получение списка всех запросов текущего пользователя.

Нужно добавить в контроллер методы для пользователя с правами выдачи снаряжения:
1. GetPendingRequests: HTTP GET запрос - получение списка всех запросов на снаряжение в статусе New.
2. ApproveRequest: HTTP POST запрос - одобрение запроса на снаряжение.
   - Должен проверять, может ли текущий пользователь выдавать оборудование с помощью UserRolesService. 
   - Если не может - возвращать 403 Forbidden.
   - Если может - менять статус запроса на Approved и возвращать 200 OK.
   - Если запрос не найден - возвращать 404 Not Found.
   - Если запрос не в статусе New - возвращать 400 Bad Request.
   - Можно отредактировать текст запроса при одобрении.
3. RejectRequest: HTTP POST запрос - отклонение запроса на снаряжение.
   - Должен проверять, может ли текущий пользователь выдавать оборудование с помощью UserRolesService. 
   - Если не может - возвращать 403 Forbidden.
   - Если может - менять статус запроса на Rejected и возвращать 200 OK.
   - Если запрос не найден - возвращать 404 Not Found.
   - Если запрос не в статусе New - возвращать 400 Bad Request.
4. IssueEquipment: HTTP POST запрос - выдача снаряжения по одобрененному запросу.
   - Должен проверять, может ли текущий пользователь выдавать оборудование с помощью UserRolesService. 
   - Если не может - возвращать 403 Forbidden.
   - Если может - менять статус запроса на Issued, заполнять поле IssuedByUserId и возвращать 200 OK.
   - Если запрос не найден - возвращать 404 Not Found.
   - Если запрос не в статусе Issued или Rejected - возвращать 400 Bad Request.
   - Выдавать снаряжение можно только по запросам в статусе New и Approved
5. ReturnEquipment: HTTP POST запрос - прием снаряжения обратно по выданному запросу.
   - Должен проверять, может ли текущий пользователь выдавать оборудование с помощью UserRolesService. 
   - Если не может - возвращать 403 Forbidden.
   - Если может - менять статус запроса на Returned, заполнять поле ClosedByUserId и возвращать 200 OK.
   - Если запрос не найден - возвращать 404 Not Found.
   - Если запрос не в статусе Issued - возвращать 400 Bad Request.

Примерное описание путей для запросов:
# зона пользователя
POST   /api/v1/EquipmentRequest
PUT    /api/v1/EquipmentRequest/{id}
GET    /api/v1/EquipmentRequest/my

# зона управления
GET    /api/v1/EquipmentRequest/pending
POST   /api/v1/EquipmentRequest/{id}/approve
POST   /api/v1/EquipmentRequest/{id}/reject
POST   /api/v1/EquipmentRequest/{id}/issue
POST   /api/v1/EquipmentRequest/{id}/return
